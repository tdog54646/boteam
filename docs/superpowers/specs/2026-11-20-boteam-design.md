# BoTeam 本地订阅 Bot 工作台
2026-11-20 · 产品与实现规格

## 用户路径
首次打开直接进入「导入本机账号」。按原生工具检测默认配置，可为指定工具选择其他配置目录。每行标注工具、来源目录、可识别身份、安装和登录状态，以及独立的执行限制。用户勾选后导入，也可跳过。完成后进入「创建 Bot 并开始聊天」。账号页始终可以重新检测、添加独立账号、重新授权、修改备注和移除绑定。

## 桌面与本地数据
首个交付目标是本机 macOS，采用 Electron、React 和 SQLite。侧栏包括新建、私聊、群聊和固定管理入口。任务运行于桌面主进程管理的官方 CLI 子进程；渲染进程仅接收元数据与聊天事件。关闭和重新打开应用后，账号、Bot、成员、任务结果与原生会话关联都可恢复。启动时把未完成的运行标记为中断，保留已收到的内容；不会静默重发任务。

## 数据边界
- 账号保存厂商、原生稳定身份、身份显示名、备注、配置来源和可核实的套餐。相同厂商的同一身份再次导入时更新现有记录。无法鉴别的来源在可验证之前仅作为待处理项。
- Bot 具有独立 ID、名称、账号外键和可选工作目录。创建后账号绑定固定。移除账号前明确告知影响，历史消息保留作者快照。
- 私聊可以反复新建。群聊保存名称与成员。每个「聊天 × Bot」保存独立的原生会话 ID。只有收到任务的成员运行，运行时再次校验成员资格。
- 每条任务保存分配对象、运行状态、原生工具、验证后的账号、流式文本、折叠工具事件和审批结果。同一聊天中同一个 Bot 的上下文串行推进，不同成员可并行。群里输入 @ 选择一个或多个成员，支持显式全体；未点名必须有明确接收人。新成员只接收自己被分配的任务和本群内自己的原生上下文。

## 原生账号与执行
- 读取官方登录状态，优先复用官方支持的账号配置目录和可安全复用的默认值。新登录使用应用专属配置目录，授权交由原生工具完成。重授权后比对原绑定身份。原客户端的登录、历史、配置保留。
- 每次打开授权都有独立的请求标识。关闭授权弹窗、重载工作台或退出应用会取消这一次请求并释放原生回调。只关闭浏览器页面时，可在等待中的弹窗直接重新开始授权。再次打开弹窗应能立即发起新的授权，旧请求的回调不可更改新请求或现有账号。
- 每次派活先通过同一运行环境中的原生身份接口核验；账号标识不匹配、API 密钥模式、身份无法核验、存在串号风险时，只阻止该成员。运行路径不得以切换全局登录来实现并发。身份、凭据与会话隔离应分别有证据。
- Codex 走官方 app-server 的 stdio 协议，以对应 profile 启动并在同一连接确认账号、启动或恢复线程及审批。Claude Code 走官方 claude，检查订阅 OAuth 身份和配置目录隔离，以 stream-json 输出、原生会话和受控授权执行。Antigravity 检测桌面端和 agy，系统共享登录且无可靠独立身份通道时在 UI 展示原因并阻止派活。
- 仅使用原生支持的凭据存储或系统安全存储；应用数据库、错误提示、工具摘要、诊断日志不保存凭据。运行环境清理 API 和代理服务等认证覆盖项。只允许已知的协议事件进入界面。权限请求显示动作概要，由用户显式允许或拒绝，应用终止时停止子进程。
- 登录失效、额度不足或原生进程退出，写入对应任务并保留重新授权入口，无自动换号。API Key Bot 仅留一个 TODO。

## Antigravity 首次检测与重复导入

首次启动与账号管理使用同一套发现逻辑。扫描已安装的 Antigravity 桌面端、官方 CLI 的原生配置和用户手动选择的外部目录。导入结果显示实际外部来源路径。BoTeam 自己保存的账号和运行目录只用于核对重复导入及执行，不构成发现结果。三种工具的候选行统一显示身份和登录状态，去掉「已导入」标签。

历史邮箱是选择 Google 账号的线索。当前登录、套餐与是否可隔离执行分别以相应的原生证据为准。新工作台可以从所选外部来源完成绑定；共享登录需要独立授权时，从导入流程直接进入官方登录并核对返回的账号。同一外部身份重复导入复用已核验的绑定，保留备注、Bot 和原生会话。验收同时覆盖空数据库、仅桌面端、仅 CLI、手动目录以及应用内有旧绑定但外部来源已消失的情况。

若外部个人 CLI 配置使用可独立复用的原生文件登录，可直接勾选导入。首次绑定须在将来执行任务的目录中，由官方 CLI 核实邮箱和订阅后再保存。原配置继续由原生客户端管理。

macOS 只有桌面端且缺少执行工具时，向导显示外部桌面配置，并提供「安装官方 agy」。用户点击后从官方发行渠道下载，核对发行包哈希与 Google 代码签名，安装到官方用户目录 `~/.local/bin/agy` 并重新检测，再从同一来源继续导入。

## 原生模型与思考强度
创建和编辑 Bot 时，从该账号绑定的原生工具读取可选模型，以及每个模型实际提供的思考强度。两项均可保留「原生默认」。切换账号重新读取选项，切换模型后重新核对强度。旧 Bot 自动沿用原生默认。单聊、群聊和续聊使用派活时保存的 Bot 设置。工具升级后已失效的显式选择必须提示用户重新选择。

Antigravity 使用官方 CLI 的 ACP 协议。桌面登录通过个人 Google OAuth 的本机回调完成，授权结果由发起请求的原生进程接收。首次设置与账号级交互数据收集选项遵循原生界面。桌面端的历史登录线索可用于发现，发送用户任务前须建立可核验并固定到账号的原生认证上下文，然后创建或恢复会话、应用原生选项、处理审批和流式回复。不能核验身份的配置显示具体恢复步骤。

## 验收证据
逐步覆盖首次发现和选择、导入幂等、第二个同厂商账号、命名 Bot、多私聊、按成员派活、同时运行、原生身份不匹配阻断、权限响应和重启续聊；重点检查群与私聊原生线程互不复用。验收报告逐厂商区分本机真实订阅任务、原生协议探测以及使用测试替身的场景，记录具体版本与未验证原因。产品不内置示例账号或伪造回复。
